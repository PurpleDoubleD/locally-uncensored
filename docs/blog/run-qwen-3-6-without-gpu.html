How to Run Qwen 3.6 Without a GPU

We spend most of this blog on running models on your own hardware. Qwen 3.6 35B A3B is the case where that advice runs out: on a laptop with integrated graphics it is not going to work, not slowly, not with a clever flag. Here is the math, then the two routes that do.

The hardware math, honestly

Qwen 3.6 35B A3B is a mixture-of-experts model. It has 35B total parameters and activates roughly 3B of them per token. That makes it quick per token once it is loaded, but it does nothing for the memory bill: at a 4-bit quant the weights are still roughly 18 to 20 GB that have to be resident, plus a gigabyte or two of KV cache and runtime overhead on top.

So the honest requirement is a 24 GB card (RTX 3090, 4090, 5090) or a Mac with 32 GB of unified memory. Anything below that either refuses to load or spills layers into system RAM, and spilled layers move at the speed of your PCIe bus, not your GPU.

What you haveRealistic outcome
24 GB NVIDIA cardRuns well at 4-bit. Use the local guide.
32 GB Mac (M3 / M4)Runs well via MLX. Local guide again.
16 GB cardLoads with offload, but you pay for it in tokens per second.
8 to 12 GB cardPick a smaller model locally, or rent this one.
Integrated graphics, no discrete GPUNot usable for this model. Rent it.

If you are in one of the last three rows, keep reading. If you are in the first two, the local setup guide has the quants, the download links and the tokens per second numbers, and we are not going to repeat them here.

Answer one: the browser Studio

The fastest route is LU Labs, the hosted layer from the same team that ships Locally Uncensored. The model runs on managed NVIDIA H100, A100 and B200 class GPUs, and your browser is the only thing you install.

  1. Create an account at lu-labs.ai and open the Studio. There is no download step, and this is also the route on a Mac because the desktop app has no native Mac build.
  2. Open the model picker above the chat input and select Qwen 3.6 35B A3B. It sits in a hosted chat catalog of 15 models, next to Hermes 3 70B, Hermes 3 405B, Euryale 70B, Qwen3 Coder 480B and Kimi K3.
  3. Drop an image into the input if you want. This model has vision, so a screenshot, a chart or a photo works as input alongside your question.
  4. Flip the think toggle for hard reasoning, code review or multi-step planning. Leave it off for casual chat, since the deliberation step costs latency and tokens.
  5. Buy a credit pack when you want more than a look at it. That is the whole setup.

What a session costs

Answer two: an API key for your own tools

If you would rather keep your existing client, take a key instead of the Studio. In your LU Labs account open Settings > Cloud API keys and create one. It carries an lu_ prefix and is shown exactly once, so copy it before you close the dialog.

The endpoint is the OpenAI chat completions shape, so most clients need three fields changed:

curl https://lu-labs.ai/api/inference/v1/chat/completions \
  -H "Authorization: Bearer lu_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen/Qwen3.6-35B-A3B",
    "messages": [{"role": "user", "content": "Explain this stack trace."}]
  }'

Base URL https://lu-labs.ai/api/inference/v1, model id Qwen/Qwen3.6-35B-A3B, key in the Authorization header. Three clients we have checked ourselves:

  • SillyTavern: API type Chat Completion, source Custom (OpenAI compatible), paste the base URL and the key, then set the model id to Qwen/Qwen3.6-35B-A3B.
  • Aider: set the OpenAI compatible base URL and key in the environment and pass the model id on the command line.
  • LibreChat: add it as a custom endpoint in the config, same base URL and model id.

If you have a machine, just not enough VRAM

The free desktop app for Windows and Linux is AGPL-3.0 and it has a Cloud switch that uses the same LU Labs account. That is the middle path: keep the 8B and 13B models you can actually host running locally for private work, and flip to the cloud for the one model your card cannot hold. Same window and the same chat history, without a second app to manage. If you are shopping for that kind of local front end in general, the LM Studio alternatives roundup covers the field.

The limits, stated plainly

  • The hardware is shared, so at busy hours there can be a short queue before your tokens start.
  • The catalog is curated. You pick from what is served, you cannot upload your own checkpoint.
  • No training on your prompts, and prompts are never sold. Accounts and billing sit in the EU.
  • Hosted text models answer as they were trained and we add no moderation layer on top of them. Hosted image and video follow the Terms of Service and the prompt is checked before it renders. Content involving minors is refused everywhere, always.
  • There is no native Mac build of the desktop app. On a Mac it is the browser Studio.

Renting a GPU is not the ideological answer on a site called Locally Uncensored, and we are not going to pretend otherwise. It is the practical answer when the model is 20 GB and your card is 8.
