LU and your models on another drive

Models are the big files: one chat model is several gigabytes, ComfyUI with PyTorch and image models easily passes 20. This guide says where LU puts things on Windows, Linux and Mac, what you can move to a second drive and how, what you cannot move, and how to move models you already have without downloading them again.

Where LU puts things

The program itself. On Windows the installer puts it in the program folder for the choice you made (current user or all users). The .deb and .rpm packages install into the system folders under /usr. The AppImage is one file that runs from wherever you saved it, a second drive included. On a Mac you drag LU into Applications. The program folder holds the app and the LU Engine and none of your files, so moving it saves very little. Details are in Install and update.

Your data and the downloads live under your user profile:

Chat models: the LU Engine folder

Under Settings, AI Backends, Model Storage the first row is "LU Engine folder". The app's own sentence explains it: "LU downloads GGUFs here and reads every .gguf in a folder you set, up to four levels down. Models here run on the LU Engine. Leave it empty and LU uses its own folder, which it reads two levels down." While the field is empty, it shows the folder it uses, as "LU's own folder:" followed by the path.

1 Make a folder on the other drive

For example D:\AI\Models on Windows or /mnt/data/models on Linux. A folder just for models is best: a very large folder, such as a whole drive, takes too long to scan.

2 Set it as the LU Engine folder

Click "Browse…" and pick the folder, or type the full path into the field. A typed path is saved when you press Enter or leave the field. "Reset" empties the field and goes back to LU's own folder; it deletes no files.

3 Download as usual

From now on, new chat models for the LU Engine download into this folder. Before a download starts, LU checks the free space on the drive that holds the folder.

LU keeps reading its own folder as well. Models that are still there stay usable, so you do not have to move everything at once.

Move chat models you already have

You can move GGUF files you already downloaded instead of downloading them again.

1 Quit LU

Use "Quit" in the tray menu. Clicking the X only hides the window, and a loaded model keeps its file open.

2 Move the files

Open LU's own folder (see the table above) and move the .gguf files into your new folder. Keep files that belong together side by side: a model split into parts (names ending in -00001-of-00003.gguf and so on) stays in one folder, and a model that can see pictures has a second file next to it, (model name).mmproj.gguf, which has to move with it.

3 Start LU and set the folder

Set the new folder as "LU Engine folder" as described above, if you have not yet. The models show up under Models, Installed again. If a chat still points at the old file and says "Model file not found", pick the model again in the model picker.

Models from Ollama and LM Studio

The same panel has two more rows. "LM Studio folder" shows LM Studio's own folder, read only: "LM Studio manages this folder. LU reads it through LM Studio when LM Studio is your chat provider." The "Ollama" row says: "Ollama keeps its own model store. LU pulls Ollama models with ollama pull; a folder cannot be set here." To put those models on another drive, change the location in LM Studio or in Ollama itself. LU has no switch for it.

"Scan for local models" finds models that are already in Ollama or LM Studio, and "Import" makes them usable for the LU Engine "without downloading or copying anything. The file stays where it is; both apps keep working." Two limits are worth knowing:

  • The scan looks only in the usual places in your home folder: Ollama's .ollama/models and LM Studio's .lmstudio/models (or .cache/lm-studio/models). Models you moved elsewhere in those apps are not found. When nothing turns up, it says "No importable models found. Looked in the Ollama store and the LM Studio models folder."
  • Import works with a file link, and such a link cannot cross from one drive to another. The link goes into LU's own folder, which is on the drive that holds your user profile. A model on any other drive fails with the message under When it goes wrong. For LM Studio models, an alternative is to set the "LU Engine folder" to the LM Studio models folder, because LU reads every .gguf in that folder. Ollama's files have no .gguf names, so for those the way is to copy the file yourself.

Image and video models: ComfyUI

On Windows and Linux, local pictures and videos run through ComfyUI, and its models live inside the ComfyUI folder under models. That folder is the one that grows. The settings are under Settings, AI Backends, ComfyUI (Image & Video).

Install ComfyUI on another drive from the start

1 Type the target into "Path"

The note under the buttons reads: "Installs to your home folder by default. Set Path above (e.g. D:\ComfyUI) to install on another drive." Type a folder that does not exist yet, or an empty one, such as D:\ComfyUI. Do not press "Connect" for this: "Connect" is for a ComfyUI that is already there.

2 Press "Install ComfyUI"

LU installs into that folder. It needs Git on the computer, and about 5 GB of free space for ComfyUI and PyTorch; on a fuller drive it warns first. Image and video models you download later through LU land inside this ComfyUI.

Move a ComfyUI you already have

1 Stop ComfyUI and move the folder

Press "Stop" in the ComfyUI section, quit LU from the tray, and move the whole ComfyUI folder to the other drive.

2 Point LU at the new place

Start LU, type the new folder into "Path" and press "Connect". "Path set successfully" confirms it. The folder must be the one that contains main.py.

3 If it does not start, repair it

Press "Start". If ComfyUI does not come up after the move, press "Repair environment": it "rebuilds the Python environment in an isolated venv (~2 GB). Models, outputs and custom nodes are left alone."

Keep ComfyUI where it is and add a model folder elsewhere

The "LU Engine folder" also works for image models. If it contains subfolders named the way ComfyUI names them (checkpoints, loras, vae, diffusion_models, text_encoders, clip, unet, upscale_models, embeddings, controlnet and a few more), LU hands those to ComfyUI. The panel then says "Image and video: LU passes (folders) from this folder to ComfyUI." Three things to know:

  • "Only a ComfyUI that LU starts gets them." A ComfyUI you start yourself does not see them.
  • LU reads the subfolders each time it starts ComfyUI, so a new subfolder arrives with the next start.
  • LU's own downloads for image and video still go into ComfyUI's own models folder. This way is for files you put there yourself.

A extra_model_paths.yaml you wrote yourself in your ComfyUI folder is never touched; LU writes its own file for this.

On a Mac

A Mac does not use ComfyUI: local pictures and videos run on Apple MLX, and the "ComfyUI (Image & Video)" section is replaced by "Local Media (Apple MLX)". Those image and video models live in the app data folder, ~/Library/Application Support/lu-labs, and the app has no setting to move them. Since 3.0.6 they are kept there instead of in the system's cache folder, which macOS may empty when the disk runs short.

The "LU Engine folder" works on a Mac for chat models. For image models it says so plainly: "Chat models in this folder are read. Image and video on the Mac run on Apple MLX, not ComfyUI, so image models in this folder are not picked up. Install those in the Model Manager, under Image."

If you pick a folder inside Desktop, Documents or Downloads, the panel warns "macOS will ask once for access to this folder." That question comes from macOS; allow it, or LU cannot read the folder.

The character trainer

Training a character locally in Character Studio needs its own Python environment, about 3 GB of downloads, and about 10 GB of free space on its drive. Where it goes can be chosen only at the first setup: the path field appears under "Set up trainer" until the trainer is installed, and then it is gone.

  • Leave the field empty and the trainer goes into the app's data folder: "Installs to your app data folder by default. Set a path above to use another drive."
  • If your ComfyUI is already on another drive, the field is filled with a folder named LU-Trainer next to it, with the note "Your model folder is on another drive, so we suggest this folder too."
  • Use a full path. A path that starts with ~ or is not absolute is refused.
  • The trainer's own caches go into the same folder. The base files for training (about 19 GB) do not: "Base model downloads always go to your configured model folder (Settings, ComfyUI), not here."
  • "Reinstall the trainer?" later sets up the environment again in the same folder. "Your training photos and downloaded base models are not touched."

Caches

The app has no setting for a cache folder. What there is:

  • On a Mac, ~/Library/Caches/lu-labs holds leftovers from downloads of image and video models. They can be fetched again, and nothing reads them once a model is installed.
  • The character trainer keeps its download caches inside the trainer folder, so they follow the place you chose at setup.
  • The helper program for remote access over the internet sits in a small folder of its own under the app data (locally-uncensored\bin under %LOCALAPPDATA% on Windows).

When it goes wrong

"This folder cannot be reached right now (drive disconnected or path missing). Models in it are hidden until it is back." The drive is unplugged, or the path has a typo. Plug the drive in; the models come back with it. A second line may say "LU cannot read that folder. Check that the drive is connected and the path is spelled the way the system spells it."

"This folder is too big to scan completely. Only the first files were read; pick a folder that holds just your models." You picked a whole drive or a big folder. Make a folder just for models and pick that.

"LU is not allowed to read that folder." The folder exists, but your user account has no access to it. "Pick a folder your own account owns, or grant this app access to that one."

"That is not a full path, so nothing can be read from it." The path starts with ~ or is relative. Use a complete path such as C:\AI\Models or /mnt/models.

"Image and video models in this folder stay invisible: ComfyUI lists only its own folders." The LU Engine folder has no ComfyUI style subfolders. Name them like ComfyUI does (checkpoints, loras, vae and so on).

"Could not link the model into the LU Engine folder ((reason)). Linking needs source and destination on the same drive. Move the models folder (Settings, Model Storage) to that drive, or copy the file there yourself." The model you wanted to import is on a different drive from LU's own folder. Changing the "LU Engine folder" does not change where Import puts its link, so copy the file into your LU Engine folder yourself, or for LM Studio models point the "LU Engine folder" at the LM Studio folder.

"A model named (name) already exists in the LU Engine models folder" A file of that name is already there. Nothing to do; the model is already usable.

"Not enough free space: (amount) short." The drive of the target folder is too full for the download. Free space there, or set a folder on a bigger drive as "LU Engine folder" and start the download again.

"Model file not found: (path)" The model was moved or the folder changed. Pick the model again in the picker, or check that the drive with the folder is connected.

"main.py not found in (path)" after "Connect". The path is not the ComfyUI folder itself. Point it at the folder that contains main.py. To install a new ComfyUI there, press "Install ComfyUI" instead of "Connect".

"(folder) already exists and is not a ComfyUI checkout." You chose an install target that already holds other files. "Pick an empty folder, or move this one aside and retry."

"Low disk space on (drive)" at the start of a ComfyUI install. "ComfyUI + PyTorch need about 5 GB." Free space or choose another drive in "Path".

"The drive holding the trainer folder ((path)) has (N) GB free and the trainer setup needs about 10 GB before anything is downloaded" Free space on that drive, or type a folder on another drive before you press "Set up trainer".

"(path) starts with ~, and this field never expands it" or "(path) is not an absolute path." In the trainer field. Type the full path, starting from the drive letter or from /.
